1. Layered Backend Architecture (N-Tier)

Separation of concerns ensuring business logic is isolated from HTTP transport mechanisms.

Layer 01
Router Layer (/routes)

The traffic controller. Maps HTTP verbs & endpoints to controllers, applying Auth, Rate Limiting, and Joi/Zod validation schemas.

Layer 02
Controller Layer (/controllers)

Handles HTTP Request & Response cycles. Extracts req.body and req.params, orchestrates services, and emits JSON responses.

Layer 03
Service Layer (Business Logic)

Encapsulates domain logic: cart totals, multi-vendor split discounts, delivery partner proximity scoring, and GPU AI calls.

Layer 04
DAO / Data Layer (/models)

Mongoose schemas enforcing database constraints, compound indexing (2dsphere for GPS), and atomic queries.

Layer 05
Middleware Interceptors (/middleware)

JWT verification, RBAC permissions (superAdminOnly, sellerOrAdmin), Multer file pipelines, and NoSQL sanitizers.

2. End-to-End Request Lifecycle Flow

Trace of a critical request (e.g. Order Placement with atomic stock decrement & socket dispatch).

4. Database Architecture & Security Strategy

Redis caching, geospatial indexing, rate limiting, and NoSQL sanitization safeguards.

⚡
Redis Caching Strategy

Catalog responses for GET /api/products are stored in Redis key caches. When sellers update garments, automated cache eviction triggers for that product ID.

redisClient.setEx(`products:cat:${category}`, 3600, JSON.stringify(data));
📍
2dsphere Geospatial Indexing

MongoDB 2dsphere indexes calculate driver proximity for 30-minute zones. Driver GPS live coordinates are kept in-memory via Socket.io to prevent disk I/O bottlenecks.

deliveryLocation: { type: "Point", coordinates: [lng, lat] }
🛡️
Rate Limiting & NoSQL Sanitization

Global rate limit of 1,000 req/15min with stricter limits on auth endpoints. All inputs sanitized via express-mongo-sanitize to strip $ and . characters.

app.use(mongoSanitize()); // Blocks NoSQL injection

5. Critical Edge Cases & Engineering Pro Tips

Proven solutions for race conditions, driver abandonment, and orphaned cloud assets.

⚡
1. Double Checkout Race Condition

When two users checkout the last remaining garment simultaneously, standard check-then-write creates stock deficits. RapidCloth uses atomic updates with conditional match:

const result = await Product.updateOne( { _id: productId, 'sizes.size': size, 'sizes.stock': { $gte: qty } }, { $inc: { 'sizes.$.stock': -qty } } ); if (result.modifiedCount === 0) throw new Error('409 Out of Stock');
⏰
2. Delivery Partner Abandonment Watchdog

If a partner accepts an order and their phone dies while in transit, the order is left stranded. BullMQ / node-cron triggers a watchdog after 180 minutes to auto-escalate to zone admins.

// Cron job checks orders stuck in 'out-for-delivery' > 3h Order.find({ status: 'out-for-delivery', updatedAt: { $lt: threeHoursAgo } })
☁️
3. Orphaned Image Upload Webhooks

Cloudinary assets uploaded before a product form submission drops connection are caught by weekly reconciliation scripts or Cloudinary incoming webhooks to keep storage clean.
